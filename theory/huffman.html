Huffman Coding

Huffman coding is a lossless data compression algorithm. In standard character encoding schemes, such as ASCII, each character typically occupies a fixed number of bits (often 8 bits). Developed by David A. Huffman in 1952, this algorithm assigns variable-length codes to characters based on their frequency of occurrence: frequently occurring characters are assigned shorter codes, whereas rarer characters receive longer codes.

Core Concept: Prefix Code
To enable the decoding of texts utilizing variable-length codes (e.g., 0 for 'A', 110 for 'B'), the algorithm ensures the generation of a prefix code. A prefix code is a coding system where no entire code word is a prefix of any other code word in the system. This property guarantees that the encoded data can be parsed unambiguously during the decoding phase.

Tree Construction

To determine the optimal code assignments, a binary tree (the Huffman Tree) is constructed using a bottom-up approach. The process operates as follows:

  • Analysis: Calculate the frequency of occurrence for each character within the target text.
  • Initialization: Create a leaf node for each character and insert them into a priority queue (min-heap), ordered by frequency from lowest to highest.
  • Merging Process: While there is more than one node remaining in the priority queue, extract the two nodes with the lowest frequencies.
  • Create a new internal node containing these two extracted nodes as children. Its frequency is set to the sum of the frequencies of its children. Insert this new parent node back into the priority queue.
  • Code Assignment: Once the tree is fully constructed, traverse from the root to each leaf. Assigning a 0 for each left branch and a 1 for each right branch generates the binary code for each character.

Python Implementation

Below is a standard implementation utilizing a Min-Heap data structure, which allows for the efficient extraction of minimal frequencies during each iteration. 

import heapq

class Node:
    def __init__(self, char, freq):
        self.char = char
        self.freq = freq
        self.left = None
        self.right = None

    # Allows the heapq module to compare nodes based on frequency
    def __lt__(self, other):
        return self.freq < other.freq

def build_huffman_tree(text):
    # 1. Calculate character frequencies
    frequencies = {c: text.count(c) for c in set(text)}
    
    # 2. Initialize the priority queue (min-heap)
    heap = [Node(char, freq) for char, freq in frequencies.items()]
    heapq.heapify(heap)
    
    # 3. Construct the Huffman tree
    while len(heap) > 1:
        left = heapq.heappop(heap)   # Node with the lowest frequency
        right = heapq.heappop(heap)  # Node with the second lowest frequency
        
        # Create a new internal node
        merged = Node(None, left.freq + right.freq)
        merged.left = left
        merged.right = right
        
        heapq.heappush(heap, merged)
        
    return heap[0] # Return the root of the tree

# 4. Generate the dictionary of binary codes
def get_codes(node, current_code="", codes=None):
    if codes is None:
        codes = {}
        
    if node is None:
        return
    if node.char is not None:
        codes[node.char] = current_code
        
    get_codes(node.left, current_code + "0", codes)
    get_codes(node.right, current_code + "1", codes)
    return codes

Complexity Analysis

The Huffman algorithm achieves high efficiency primarily through the use of a binary heap data structure.

Metric Complexity Explanation
Time Complexity $O(N \log N)$ Where $N$ represents the number of unique characters. Extracting the minimum elements and inserting the new parent node into the min-heap requires $O(\log N)$ time. This operation is repeated $N-1$ times. (Note: the initial frequency counting process requires $O(L)$ time, where $L$ is the total length of the text).
Space Complexity $O(N)$ The resulting binary tree will contain exactly $2N - 1$ nodes, requiring memory proportional to the number of unique characters in the dictionary. The priority queue also stores up to $N$ nodes.
